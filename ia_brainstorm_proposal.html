Brainstorming & Project Proposal

A structured guide to finding an idea, testing its suitability, and writing your proposal.

INTRO What makes a great IA project?

The IB CS Internal Assessment is graded on your ability to design, build, and evaluate algorithms. The quality of your project depends on how algorithmically interesting it is, not on how polished it looks.

📊
Substantial Data
Your project should work with a meaningful dataset, enough that your algorithm has something interesting to do. Think hundreds or thousands of records, not a handful.
⚙️
Impressive Algorithm
Go beyond what the syllabus covers. Higher-achieving IAs demonstrate technical learning beyond the course. Pick something you had to genuinely study and understand.
🌍
Real-World Use
Your project should solve a genuine problem. You should be able to describe a specific type of user who would benefit from it.
Key principle Start with the algorithm, not the app. Ask: "What interesting algorithm do I want to learn and demonstrate?" Then design a project around it.

AVOID Projects to steer clear of

These project types offer little algorithmic complexity. Avoid them unless you can add a genuinely novel algorithmic element.

To-do / task app Blog platform Room / appointment booking Inventory / library system Basic CRUD web app Simple quiz app Recipe manager Contact book

These are CRUD apps (Create-Read-Update-Delete). They are reasonable software projects, but they do not showcase algorithms, which is what the IA grades you on.

Your task Pick 2 or 3 algorithms from the resource above that interest you. Research each briefly, then move on to Step 2.

STEP 2 Generate three project ideas

For each algorithm you have shortlisted, ask: "What real-world problem could this algorithm help solve, using a substantial amount of data?" Use the worked examples below as a model, then generate your own.

Worked example A
Public Transit Route Optimiser
📊 GTFS transit data (1000s of stops) ⚙️ Dijkstra / A* algorithm 🌍 Real-world: commuters, city planners

Loads a real city's public transport network as a weighted graph. A user inputs a start and end location; the program finds the fastest or fewest-transfer route. Demonstrates graph traversal on a large real dataset, with output a real commuter would use.

Worked example B
Spam Email Classifier
📊 Labelled email dataset (10,000+ messages) ⚙️ Naive Bayes classification 🌍 Real-world: email security, productivity

Trains a probabilistic classifier on a publicly available spam/ham dataset. The program learns word frequencies per category and classifies new email text with a confidence score. Involves real data pre-processing, model training, and evaluation with precision/recall metrics.

Worked example C
Personalised Workout Recommendation App
📊 User-generated workout logs (sets, reps, load, rest) ⚙️ k-NN or collaborative filtering 🌍 Real-world: fitness tracking, training planning

Users log their workouts over time. The app analyses each user's history alongside other users' data to recommend the next session: which exercises, at what weight, and at what volume. The algorithm runs on data produced by the users themselves rather than a static external dataset. Requires designing a user account system, a data schema for workout records, and a similarity or recommendation algorithm that improves as more data is collected.

STEP 3 Apply the 80% test to each idea

For each of your ideas, ask yourself these questions honestly. If an idea scores well across all of them, it is a strong candidate.

  • Am I interested in the algorithm? You will be spending weeks on this.
  • Am I roughly 80% confident I can build it? Not 100% (too easy) and not 40% (too risky). Aim for something with a reasonable stretch.
  • Does my project require a substantial dataset? Where will the data come from? Is it publicly available, or will users generate it?
  • Is the algorithm the centrepiece, not just a footnote? Someone reading your code should be able to locate the interesting algorithm immediately.
  • Does a real person have this problem? Can you describe a specific type of user who would benefit from what you are building?
  • Does the algorithm go beyond the syllabus? Higher-achieving IAs demonstrate learning beyond what was taught in class.
  • Is it feasible in the time available? Can you realistically reach a working, testable product within the IA timeline?
